# 本地内容分类模型

扩展用一个离线小模型判断"正在播放什么"，决定哪个角色出场。

## 它做什么

输入只有四样：标题、歌手或频道名、网站域名、时长（播放器知道时）。输出：

| 字段 | 取值 | 没把握时 |
|---|---|---|
| 类型 | music / video / live / podcast | 记作 `other`，走通用池 |
| 曲风（仅音乐） | 10 类，同 `GENRES` | 为空，走通用池 |
| 视频类别（仅视频） | ent（娱乐）/ info（讲解） | 为空，任何视频角色都可能出场 |

模型结构：标题和频道的 1～4 字符 n-gram、单词、词对，加网站和时长档位，哈希到 131,072 个桶，三个线性分类头（int8 量化），再加一张 25,826 个歌手名 → 曲风的对照表。单条判断不到 1 ms，不需要 NPU 或 WebAssembly。

## 文件

| 位置 | 内容 |
|---|---|
| `public/model/kobutai.bin` | 模型权重（2.1 MB） |
| `public/model/artists.tsv` | 歌手名 → 曲风（0.48 MB） |
| `public/model/config.json` | 站点规则、置信度阈值、歌手表加分 |
| `src/lib/tagging/model/classifier.ts` | 推理代码，和参考实现（Python）逐条一致 |
| `src/lib/tagging/model/local.ts` | 加载、映射到扩展的标签、转交 AI 的阈值、直播站点 |
| `tests/fixtures/model-vectors.json` | 559 条参考输出，`classifier.test.ts` 逐条核对 |
| `tests/fixtures/real-titles.json` | 383 条真实标题（2026-10-13 从榜单和热门页抓取，训练时没见过），用于准确率测试 |

## 准确率

383 条真实标题（类型和曲风都对才算对；不含视频类别，因为关键词规则不输出它）：

| | 完全判对 |
|---|---|
| 本地模型 | 86.9% |
| 原来的关键词规则 | 59.5% |
| 本地模型 + AI（模型置信度 < 0.9 时转交，约 32%） | 研究中测得约 95%（AI 用 DeepSeek V4.1 Flash） |

扩展自带的 41 条手工标注标题上，模型 90.2%、关键词规则 92.7%（规则就是对着这些标题写的）。剩下的差别主要是标注习惯不同，例如没有标出动画名的 YOASOBI 歌曲算 J-pop 还是动漫。

## 已知的局限

- **新歌手、没有线索的标题**只能靠猜，这是只看文字的上限。歌手表需要随榜单定期更新。
- **Spotify 上的播客**：扩展现在拿不到网址（`/episode/`），模型只能从标题判断。以后可以让 Spotify 适配器把"这是播客"传给 `platformCategory`。
- **直播**：播放器报告的时长是无限大时，快照里会带 `live: true`；另外 `local.ts` 按域名（`LIVE_HOSTS`）告诉模型这是直播。没有核实的情况：YouTube 直播是否报告无限大时长；个别 HLS 点播播放器可能短暂报告无限大，会被当成直播或音乐流。
- **单页网站换视频**：标签在内容第一次开始播放时确定，之后不再重算。如果这一刻播放器的时长或直播状态还没更新（例如 YouTube 切换视频的瞬间），会用到不准的时长。只有少数判断依赖时长（真实标题里 383 条中 3 条）。
- **K-pop 归在 western-pop**（和欧美流行一起），是标注规范的选择。

## 更新模型

模型在单独的 `kobutai-classifier` 项目里训练（数据、训练脚本、评估、研究报告都在那里）。更新时：

1. 在那个项目里重新训练、评估，并生成新的 `model/test-vectors.json`。
2. 把 `model/kobutai.bin`、`model/artists.tsv` 复制到这里的 `public/model/`；`config.json` 去掉 `labels` 字段后复制过来。
3. 把 `test-vectors.json` 复制成 `tests/fixtures/model-vectors.json`。
4. 运行 `npm run check`。`classifier.test.ts` 不通过说明推理代码和参考实现不一致，必须先修。

## 数据来源说明

训练数据包括大模型生成的标题样本、人工整理的歌手名单，以及 Apple 公开分类榜单（使用条款尚未核实）。上架收费前需要确认 Apple 榜单数据的使用条款，或者去掉这部分数据重新训练（真实标题上的曲风准确率约降 2.5 个百分点）。
